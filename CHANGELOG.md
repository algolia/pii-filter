# Changelog

## Unreleased

### Changed
- Test data is synthetic only. Phones come from regulator fiction ranges
  (ARCEP, Bundesnetzagentur, Ofcom, NANPA), emails from RFC 2606/6761 domains,
  IPs from RFC 1918/5737, cards from published gateway test numbers, IBANs from
  the SWIFT IBAN Registry examples. National IDs stay inside unissued bands
  (`corpus/synth_ids.py` lists each band and its strength); FR_TAX_ID bodies
  are sequential (0000000001, ...) because no unissued range is known.
- The Tier-2 mini-eval addresses are invented (fictional communes, generic
  streets). ADDRESS exact F1 0.385 -> 0.431, not a significant change (paired
  McNemar p = 0.59).
- Docs describe a standalone toolkit: generic consumers, public `go get` and
  `pip install git+https://` installs.

## 0.2.0 — 2026-11-16 · French and Spanish national identifiers

### Added
- Six national-identifier entities in Python and Go, all default policy
  `redact` with typed masks (`[FR_NIR]`, …):
  - `FR_NIR`: French social security number, 15 characters, mod-97 key,
    Corsica's 2A/2B read as 19/18, first digit 1/2/7/8.
  - `FR_TAX_ID`: French numero fiscal (SPI), 13 digits, first digit 0-3, first
    ten digits mod 511 equal the last three.
  - `FR_SIREN` / `FR_SIRET`: company and establishment numbers, Luhn. A SIRET
    also needs a Luhn-valid SIREN; La Poste's (356000000) are valid on Luhn or on
    its digit-sum rule.
  - `ES_DNI` / `ES_NIE`: Spanish national and foreigner IDs, mod-23 control
    letter, NIE prefix X/Y/Z read as 0/1/2.
- Tier 1.5 keyword gate: `requires_context`, `context_keywords` and
  `context_window` in `spec/entities.yaml`, implemented with one fold table in
  `src/pii/context.py` and `context.go`. FR_SIREN and FR_SIRET use it (Luhn alone
  passes one random number in ten). The whole keyword must lie inside the
  window (40 characters for SIREN/SIRET). Combining marks are folded away, so a
  keyword typed decomposed (NFD) matches. Findings stay `tier: 1`.
- `spec/schema/entities.schema.json`, the JSON schema of the entity spec.
- Corpus: `fr_nir`, `fr_tax_id`, `fr_siren`, `fr_siret`, `es_dni`, `es_nie` and
  `eu_overlaps` (254 rows, 140 labeled spans), generated by
  `corpus/synth_ids.py` with a fixed seed: positives, checksum negatives and near
  misses, plus keyword-absent, keyword-too-far and keyword-after rows for the
  gated entities. Bodies come from ranges meant to be unissued (NIR birth months
  14-19, DNI from 99 000 000, SIREN from 000); the generator header says how
  strong each choice is. Tests pin that the generator reproduces every corpus
  file and stays in those ranges.
- Go tests that read `src/pii/entities.yaml` and fail when the Go analyzer order,
  default policies or keyword gates drift from the spec.

### Changed
- matplotlib is no longer a core dependency: it moved to the `bench` extra
  (`pip install "algolia-pii[bench]"`). `import pii`, detection and policy never
  needed it; `import pii.bench` without the extra raises an `ImportError` naming
  it. The core install is pyyaml only.
- The Go corpus test reads spans as code-point offsets, as Python writes them.

### Behaviour changes
- **Go equal-span tie-break.** Overlap resolution in Go now breaks equal-span
  ties on score, then spec order, as Python always did. Example:
  `x 3782 822463 10005` was PHONE in Go before 0.2.0 and is CREDIT_CARD now,
  matching Python (so `SpecPolicy()` rejects it instead of redacting it). The
  national identifiers sit before PHONE and CREDIT_CARD in the spec so a
  checksum-valid ID wins a span the phone or card reading also claims.
- **New redactions on lookalikes.** Before 0.2.0 a bare 13- or 15-digit run was
  never flagged. FR_TAX_ID now fires on about 0.09% of 13-digit millisecond
  timestamps and French EAN-13 barcodes, FR_NIR on about 1.0% of 15-digit
  numbers starting 1/2/7/8, ES_DNI on about 3.9% of "8 digits + capital letter"
  codes (200,000 random strings each). Map an entity to `allow` or `flag` in
  your policy to opt out.
- **Diners-shaped numbers after a keyword.** A Luhn-valid 14-digit number
  starting 30, 36 or 38 within 40 characters after a SIREN/SIRET keyword is
  FR_SIRET (`redact`), not CREDIT_CARD (`reject`). Pass an explicit policy if you
  need reject-on-card there. Some keywords are generic (`rcs`, `business id`,
  `company number`).

### Known limits
- A checksum-invalid NIR, numero fiscal or SIRET written in digit groups is still
  reported as PHONE. A 14-digit SIRET starting 30, 36 or 38 with no keyword is
  reported as CREDIT_CARD (it is also a valid Diners number).
- DNI/NIE letters must be uppercase. The NIR month and department are not
  checked against INSEE tables.
- A valid checksum proves shape, not issuance.
- Python and Go agree on the corpus, not everywhere: pre-existing disagreements
  on CREDIT_CARD, PHONE and IP edge cases remain (about 124 per 20,000 fuzz
  strings, measured before 0.2.0).

### Provenance
- Every check is implemented from the public algorithm descriptions (INSEE's NIR
  definition and its mod-97 key, the numero fiscal mod-511 rule, Luhn, the DNI
  letter table). No code, docs or test vectors were taken from another library;
  the corpus numbers are random and generated forward from those algorithms.

## 0.1.0 — 2026-06-29 · first consumable library

The Tier-1 library becomes installable as a dependency: pip-installable,
documented, tested in CI, with a README chart of its measured precision.

### Fixed
- Python wheel was not self-contained: `pip install git+...` threw
  `FileNotFoundError` at first detect because `spec/entities.yaml` was resolved
  via a repo-root relative path absent from the wheel. The canonical spec now
  lives under the package (`src/pii/entities.yaml`); `spec/entities.yaml` is a
  symlink to it (single SSOT, zero drift). `spec.py` resolves arg → packaged
  resource (`importlib.resources`) → repo-root checkout fallback. Verified by
  installing the wheel into a clean venv and running a detection.

### Added
- `docs/integration.md` — howto for depending on the lib from Go
  (`go get`) and Python (pip/poetry git dep, now self-contained),
  full API surface, the six policy actions, and an explicit Tier-1-available /
  Tier-2-not-shipped boundary plus honest limits.
- README hero dataviz, rendered live from the corpus (no hardcoded numbers) and
  reproducible via `pii-bench hero`: precision/recall baseline-vs-validated with
  Wilson CIs, false-positives-by-entity collapsing 32→0, per-entity precision
  dumbbell, and a live detect+redact demo.

### Changed
- README status: v1 is usable today (both `go get` and `pip install` work);
  Tier-2 (names/addresses) is not implemented.

### Infra
- CI (GitHub Actions): `go test ./...` and `poetry install` + `pytest` on
  push and pull request.

### Notes
- Single source of truth survives packaging via a symlink, never a copy — the
  build backend (poetry-core) dereferences symlinks pointing *into* the package
  but rejects ones pointing *out*, so the real file lives under the package and
  the documented path symlinks to it.
- Calibrated honesty preserved end to end: the hero carries its n and Wilson
  intervals; "tripwire on clean data, not a compliance guarantee" stays loud.
